# Data map — what 2J stores, where, and who can reach it (verified in code, Sprint 3)

Legend: **AES** = AES-256-GCM at rest with a key derived (HKDF, per-feature `info`) from `./data/secret`; **plain** = readable JSON on disk. All traffic is HTTPS (Caddy/Let's Encrypt → nginx → API on a private network).
The key sits next to the data (see Encryption caveat), so "AES" protects against a *partial* leak (one file, a stray copy), not against someone who can read the whole `./data`.

The shared exercise note (one text per member + exercise, up to 500 characters, edited by the member and by the staff who may reach them) is kept in `exercise-notes.json` (plain, like the Bunker file): it is included in the member's export and removed with their account.

Bunker PINs (4 digits per member, `bunker.json`, plain) and admin kiosk codes (6 digits) are by design shown to admins/trainers; they only mint a kiosk token for check-in/workout display, not an app session.

## Encryption caveat (unchanged, now explicit)
`state-*.json` and OAuth/AI credentials are encrypted; `db.json`, chat, friends, social, notifications, bunker are not. Because the AES key derives from `./data/secret` stored beside the files, a full copy of `./data` decrypts everything. Backups are therefore encrypted *before leaving the VPS* with a different key (passphrase). Proposed, **not executed** (needs a decision): see `docs/ENCRYPTION_PROPOSAL.md`.

## AI — payload boundaries
Sent by the member's Coach (only with the member's Coach consent): handle (HMAC pseudonym, never uid), language/unit, gym equipment, plan (routines/programs), recent logged sets/effort/PRs (review window ≤ 12 weeks / 60 sessions), weigh-ins + goal (review only), the member's own Coach intake (goal, days, limitations, likes, notes) and age/sex/height, library slice, protocol rules.
Never sent: Health/activity/HR/sleep, WHOOP/Strava data or ids, body composition, measurement tests, workout session notes (**fixed in Sprint 3**), chat, social, Community, account name/uid, credentials, push data. Test: `api/test/payload.test.js` ("health, WHOOP, composition … never reach the provider"). Fallback without AI: the deterministic engine (progression, swaps, Intelligence) runs on the device.
Trainer AI ("Generate with AI", `coach/trainer-jobs.js` + `payload.buildTrainer`) is started by a trainer or the administrator who has access to the member (the existing staff access rule); there is no separate member consent switch (owner decision, 2026-10-21; the old `S.staffAi.consent` is no longer read anywhere). Its provider (Claude) receives only the member's current routines and programs, the trainer's brief and a pseudonymous handle — no workout history, profile, name, measurements or Health data. The staff follow-up analysis (`coach/followup-ai.js`) sends only compact calculated facts, without names, ids or notes, and is also started by staff with access to the member.

Auxiliary AI is Google Gemini for exercise import matching and one-shot body-composition, routine and machine scans. Scans require a separate explicit confirmation for each selected file, enforced again by the API before any scanner/provider call. The scanner returns extracted fields but does not save the file or results to account storage; the caller reviews the returned result before using the existing save flow. This per-file scan consent is not persisted or reused as Coach consent.

## Accepted risks (owner decisions, Sprint 3 close)
- **WebAuthn `userVerification: 'preferred'`** is kept (not `required`): a possession-only authenticator without PIN/biometric could sign in. Platform passkeys (phones, Windows Hello, iCloud/Google) always verify the user, so the practical exposure is hardware keys configured without a PIN.
- **Bunker PIN stays 4 digits.** Limits: 20 failures/min per IP and 5/min per guessed PIN, exponential block up to 5 min; a PIN only mints a 4-hour kiosk token (check-in/workout display), never an app session. A *distributed* attack (many IPs) can walk the 10 000 space; if that ever matters, move to 6 digits or add a per-account lock (UX change, not done).
